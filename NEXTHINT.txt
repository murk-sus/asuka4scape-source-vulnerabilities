Ghidra analysis — open kernel.raw (build 24A437, iOS 27.0)

==============================================================
TARGET 1 — necp_client_copy_result @ 0xFFFFFFF00A4EAC7C
==============================================================
В Ghidra: Navigation → Go To → 0xFFFFFFF00A4EAC7C.

Что искать:
1. Пролог (первые 10-15 инструкций). Найти:
   - pacibsp
   - sub sp, sp, #N           → размер стек-фрейма
   - stp x28, x27, [sp, #...] → сохранение callee-saved
   - mrs x20, tpidr_el0       → atomic base (или SP)
   - ldr x8, [x0, #...]       → client pointer из аргумента
   Определить: какой регистр хранит flow pointer (обычно x19..x24).

2. Найти цикл LIST_FOREACH: паттерн
   ldr xN, [xM, #off_next]
   cbz xN, loop_exit
   ... body ...
   b   loop_start
   Записать: offset_next, регистр flow.

3. ВНУТРИ цикла — все ldr xK, [x_flow, #imm].
   Для каждого: отметить, что дальше с ним делают.
   Наша цель: инструкция, после которой идёт:
      - add x0, sp, #buf
      - mov x2, #len
      - bl memcpy
      - затем bl copyout ИЛИ syscall(SYS_copyout)

   Offset из ldr xK, [x_flow, #imm] — ЭТО NCF_ASSIGNED_OFF.
   В нашей v18/v19 было 0x20 из старого анализа — проверить.

4. Проверить: есть ли ldr из [x_flow, #imm+8] сразу после —
   это assigned_length.

5. Если НЕ найдено ни одного ldr xK, [x_flow, #imm] который
   ведёт к memcpy → функция НЕ читает flow и не может быть
   использована для kread. Переключиться на TARGET 3.

TARGET 2 — necp_client_add_flow @ 0xFFFFFFF00A4E843C
==============================================================
Что искать:
1. Вызов kalloc (bl → функция kalloc) в прологе.
   - Аргумент w0 = размер структуры.
   - Записать размер: 512 / 1024 / 2048 — это зона kalloc.
2. Найти место, куда пишется flow->assigned_results.
   Обычно сразу после kalloc:
      str xzr, [x_flow, #NCF_ASN_OFF]
   Это подтвердит offset.
3. Найти где записывается user-supplied TLV:
      ldr x0, [x_req, #...]
      memcpy...
   Проверить: есть ли проверка длины (cmp w, #max).

TARGET 3 — TLV parser (искать по строке "tlv" в symbols)
==============================================================
Функции: искать символы с "tlv" в имени.
Что искать:
1. necp_get_tlv_at_offset(buf, buflen, type, &out, &outlen)
2. Внутри — арифметика с uint32:
      u16 type; u16 len;
      if (off + len + 4 > buflen) return -1;
      ОПАСНО: если off + len переполняется по uint32 → OOB read
      длиной до 4 ГБ.
3. Проверить наличие necp_set_tlv_at_offset (симметричный).
   Если есть — OOB write → kwrite primitive.

==============================================================
TARGET 5 — socket / pipe kalloc path
==============================================================
Альтернативный heap-spray, если NECP-flow не в kalloc.1024.
Что искать:
1. Socket allocation: soalloc() → kalloc(size) или zone?
   - Зона: caches "socket" или kalloc.
2. sendmsg() → mbuf_alloc или kalloc?
3. Pipe buffer allocation: размер 16 KB (PIPEBUF).
   - Если pipe buffer в kalloc.1024 при определённом fcntl —
     можно использовать pipe() вместо NECP.
